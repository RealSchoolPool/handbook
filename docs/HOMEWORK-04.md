# Домашнее задание №4 — «Список, фильтр, печать»

**Срок:** к занятию в четверг 24.09.
**Время:** 40–60 минут.
**Сдавать:** файлы `.py` — в чат или принести завтра. Завтра эти же файлы станут вашим
первым коммитом в репозиторий команды.

> Это задания, которые мы должны были сделать в среду в классе. Пропал свет — поэтому они
> переехали домой. Проверяльщик тот же, что на занятии: он скажет, что не так, и подскажет.

**Про формат:** правило «только `.md`» — для текстовых работ. Код сдаётся файлом `.py`.

---

## Шаг 0. Скачать задания

Git для этого не нужен.

1. Скачайте архив: **https://github.com/RealSchoolPool/handbook/archive/refs/heads/main.zip**
2. Распакуйте. Внутри папка `handbook-main/lessons/` — там `check.py` и задания.
3. Откройте терминал **в этой папке** и проверьте, что всё работает:

```
python check.py
```

Должен появиться список заданий. Если пишет, что `python` не найден, — попробуйте `python3`.

## Шаг 3. Та же форма — на данных вашего проекта

Создайте файл `project.py` и сделайте то же, что в `task04`, но на наборе данных, который
ваша команда выбрала на занятии.

`check.py` этот файл не проверяет: у каждой команды свои данные. Проверяете вы сами —
по критериям ниже, и ровно так, как это делает `check.py`.

### Сначала вопрос, потом код

**Первая строка файла — комментарий с вопросом, на который отвечает программа.**

```python
# Какие вещи до сих пор никто не забрал?
```

Если не можете сформулировать вопрос одной строкой — непонятно, что писать дальше.
Это не формальность: вопрос и есть задача, а код — только ответ на неё.

Например:

| Команда | Вопрос |
|---|---|
| `lost&found` | Какие вещи до сих пор никто не забрал? |
| `Inch_P_Sanel` | Что сдавать завтра? |
| `Vor_tag` | Где в эту неделю были переносы? |

Можно свой вопрос — главное, чтобы на него отвечала одна проверка `if`.

### Форма данных

Как в `task04`: список, в котором каждая строка — несколько значений в скобках.

```python
items = [
    ("зарядка",  "каб. 12",      "15.09", "у дежурного"),
    ("наушники", "коридор 2 эт", "16.09", "никто не забрал"),
    # ... дальше ваши строки
]
```

Поля — те, о которых договорилась команда. У всех строк одинаковые.

### Самопроверка — как это делает `check.py`

**До запуска** выпишите на бумаге, какие строки должна напечатать программа. Потом запустите:

```
python project.py
```

и сравните. Совпало — готово. Не совпало — ошибка либо в условии, либо в данных, и найти её
надо до того, как сдавать.

Это ровно то, что делает `check.py`: у него заранее записан правильный ответ, и он сравнивает.
Сегодня вы впервые делаете это сами.

## Критерии приёмки

### `task03` и `task04`

- [ ] `python check.py task03` — засчитано
- [ ] `python check.py task04` — засчитано

Замечания по оформлению под зачётом — не ошибка, но завтра на ревью их попросят поправить.

### `project.py`

- [ ] Первая строка — комментарий с вопросом
- [ ] Данные — один список в одной переменной, не меньше 10 строк из набора команды
- [ ] У всех строк одинаковые поля
- [ ] Один цикл `for` по списку
- [ ] Одно условие `if`, и оно отвечает на вопрос из первой строки
- [ ] Печатается только нужное, а не вся строка целиком
- [ ] `python project.py` запускается без ошибок
- [ ] Напечаталось ровно то, что вы выписали заранее
- [ ] В данных нет ни одного имени ученика
- [ ] Можете объяснить каждую строку своими словами

Последний пункт завтра проверим вслух. Это правило для любого кода, откуда бы он ни взялся.

## Если нет компьютера или Python дома

Это нормально и не повод пропускать. Решение `task03`, `task04` и `project.py` можно написать
**в тетради или прямо сообщением в чат** — завтра в первые пятнадцать минут прогоним через
`check.py` в классе.

Не сделанное задание хуже, чем сделанное на бумаге.

## Антипаттерны

| Что сдают | Что не так |
|---|---|
| Пять отдельных `print` в `task03` | Завтра предметов станет двадцать. Нужен цикл — ради него задание и есть |
| `project.py` без вопроса в первой строке | Непонятно, правильно ли работает программа: не с чем сравнить |
| Данные выдуманы на ходу | Набор выбран командой на занятии — берите его. Выдуманные данные всегда аккуратные и ничему не учат |
| Печатается вся строка целиком | Пользователю нужен ответ на вопрос, а не таблица. Фильтр — это ещё и выбор, *что* показать |
| Проверка «на глаз» после запуска | Выписать ожидаемое **до** запуска. После запуска любой вывод кажется правильным |
| Код, который не можете объяснить | Неважно, откуда он: из подсказки, от соседа или от нейросети. Не объясните — не засчитано |

### Заметка для преподавателя

- `check.py` закрывает `task03` и `task04` полностью. Ручная проверка нужна только для
  `project.py`, и чеклист построен так, чтобы её можно было сделать за минуту на человека.
- Пункт «выписать ожидаемое до запуска» — главный в задании. Это первое знакомство с идеей
  теста, до всяких тестов. На неделе 5, когда дойдём до тестов, на него можно будет сослаться.
- Если кто-то сдал на бумаге — не отдельная проверка, а первые 15 минут четверга: прогнать
  через `check.py` вместе.
