# Занятие 6 — Репозитории команд и первый коммит каждого

**Четверг 24.09, 11:15–13:00 — 105 минут, один блок.** Без перерыва и без второй половины дня.

---

## Что изменилось

В [плане недели](WEEK-03.md) четверг рассчитывался на три часа: GitHub, три репозитория,
коммит от каждого и сборка walking skeleton. В 105 минут это не влезает. Значит, резать —
и решить заранее, что именно, а не в процессе.

> **Ядро дня, которое не режется:**
> у каждой команды есть репозиторий, и **каждый студент сделал в него хотя бы один коммит**.

Сборка скелета, конфликты, git в терминале — уезжают на пятницу или на следующую неделю.

---

## Главное решение: первый коммит делается через веб-интерфейс

Не через терминал. Причина простая и арифметическая.

Установка git, настройка имени и почты, аутентификация через токен или SSH-ключ — это то,
на чём тринадцать человек застревают гарантированно и надолго. Одна только аутентификация
съедает урок целиком. В терминале до первого коммита сегодня дойдут двое-трое, остальные
будут смотреть в чужой экран.

В веб-интерфейсе: открыл репозиторий, нажал «создать файл», написал, нажал Commit. Ноль
установки. При этом коммит настоящий, в настоящем репозитории, с их именем в истории —
а именно это сегодня и нужно.

Терминальный git придёт, когда будет трёхчасовой слот. Порядок «сначала понять, что такое
коммит, потом научиться делать его из консоли» ничем не хуже обратного, зато до конца
доходят все.

## Тайминг

### 11:15–11:25 · Где мы и цель дня (10 мин)

Цель — одним предложением: **«к концу занятия у каждого из вас будет коммит в репозитории
своей команды»**.

Быстрая перекличка ников. У кого нет аккаунта — заводит прямо сейчас, сосед помогает.
Не оставлять это на потом: человек без аккаунта выпадает из всего занятия.

### 11:25–11:40 · Что такое репозиторий команды (15 мин)

Рисунок на доске, три сущности, больше ничего:

```text
   твой браузер  ──────►  GitHub
                          репозиторий = папка с историей
                          коммит = сохранённое изменение,
                                   с подписью и объяснением
```

**Не упоминать сегодня:** ветки, clone, remote, merge, pull request. Они не нужны, а каждое
лишнее слово здесь стоит минуты позже.

Одно правило про сообщение коммита, сразу: пишем, **что** сделали. `add data from my notes` —
да. `fix`, `update`, `123` — нет. Сообщение читает тот, кто через месяц будет искать, когда
всё сломалось.

### 11:40–12:25 · Первый коммит каждого (45 мин)

Ядро дня. Всё остальное подчинено этому.

1. Заходят в репозиторий своей команды по приглашению.
2. Создают файл `data/<свой-ник>.md`.
3. Вставляют туда свои строки из [ДЗ №3](HOMEWORK-03.md).
4. Коммитят с осмысленным сообщением.
5. Открывают вкладку с историей и **видят своё имя**.

Последний пункт не декоративный: момент, когда человек видит себя в истории проекта, — это
то, ради чего стоило возиться с аккаунтами.

**Не двигаться дальше, пока коммита нет у каждого.** Кто закончил — помогает соседу; объяснить
другому и есть способ понять самому.

### 12:25–12:50 · Данные команды становятся одним файлом (25 мин)

Теперь у команды четыре-пять файлов, и почти наверняка с разными полями: кто-то написал дату
как `15.09`, кто-то `15 сентября`, кто-то забыл колонку.

Задача: свести к одному `data/items.md` с **одинаковыми полями**.

Это первый настоящий спор о формате данных, и он должен произойти между ними, а не в твоей
голове. Правило: сначала договариваются словами, потом **один** человек правит файл, остальные
смотрят. Если править одновременно — GitHub не даст, и это хорошо.

Здесь же всплывёт первый конфликт: двое открыли один файл, один сохранил, второй получил
отказ. Не лечим и не объясняем механику — показываем и говорим: «вот это мы починим
инструментом на следующей неделе». Боль должна запомниться раньше лекарства.

### 12:50–13:00 · Фиксация и что завтра (10 мин)

- Где что лежит: `data/` — данные, `README.md` — описание проекта.
- Завтра: программа читает этот файл и печатает отфильтрованное, потом сервер.
- Группа C курса: инструкция по деплою нужна к завтрашнему дню.

Студентам C курса с git веб-интерфейс не нужен, и держать их в нём — потерять их внимание.

| Кто | Задача на сегодня |

| Те, у кого git уже стоит | Настроить у себя, клонировать репозиторий команды, сделать коммит из терминала |
| Они же | Написать короткую инструкцию «как склонировать и закоммитить из консоли» — по ней остальные пойдут на следующей неделе |
| Հայկ и Ավետ | `.gitignore` в трёх репозиториях и проверка, что внутрь не уехало лишнее — их роль |

Инструкция, написанная студентом для студентов, работает лучше твоей: он помнит, где сам
спотыкался.

## Если пойдёт не так

| Ситуация | Что делать |
|---|---|
| Половина без аккаунтов | Первые 15 минут — регистрация парами. Сжимается сведение общего файла, оно уезжает на пятницу |
| Данных из ДЗ №3 нет | Коммитят пустой шаблон с одними заголовками полей. Сегодня учимся коммитить, содержимое вторично |
| Кто-то вписал в данные фамилию | Поймать до конца занятия и убрать. Не наказание, а живой повод объяснить, почему репозиторий приватный |
| Не успеваем к 13:00 | Режется блок 12:25–12:50. Первый коммит каждого не режется ни при каких условиях |
| Интернет лёг | Данные сводятся к общему формату на бумаге — это всё равно нужно сделать, — а коммиты переносятся на пятницу |
| Кто-то закоммитил чужой файл или сломал чужой | Отличный момент: показать историю, найти, кто и когда, откатить. Первый практический аргумент в пользу git |
